# Phase 4 Diarization Quality Report

Generated by `src/diarization/evaluate.py` against all 199 files in
`data/diarized/` (run completed 2026-08-13, evaluated 2026-08-14).

## Why reference-free

There's no ground-truth speaker-labeled reference for this corpus (no
manual RTTM annotations exist), so the standard diarization accuracy
metric -- Diarization Error Rate (DER) -- can't be computed. This report
instead audits structural signals already present in each diarized file
(speaker count, per-speaker time share, turn fragmentation, isolated-text
retention vs. the Phase 3 transcript) to flag files worth a manual listen.
Same approach and rationale as the existing Phase 3 reference-free
transcript-quality audit (`src/transcription/quality.py`).

## Headline result

**199/199 files processed. Zero files triggered any of the six
"likely-a-real-problem" flags.** The only flag that fired at all was one
purely informational one, on 93/199 files (see below) -- and it does not
indicate a defect.

| Flag | Files | Meaning |
|---|---|---|
| `single_speaker_detected` | 93 / 199 | Only one speaker label found in the whole file |
| `low_target_speaker_share` (<15%) | 0 | Would indicate likely misidentification (e.g. an interviewer talking more than Sadhguru) |
| `many_speakers_detected` (>5) | 0 | Would indicate probable over-segmentation/noise |
| `fragmented_turns` (>30% turns <0.3s) | 0 | Would indicate choppy/noisy diarization |
| `implausibly_slow` / `implausibly_fast` speech rate | 0 | Would indicate misaligned word-to-speaker attribution |
| `low_text_retention` (<5% of transcript words kept) | 0 | Would indicate most content got dropped -- likely misidentification or a broken alignment |
| `possible_repetition_artifact` | 0 | Would indicate segments stitching into an accidental loop |

### On `single_speaker_detected`

This flag fires when pyannote found only one speaker label in the entire
file -- **it is not necessarily a problem**. Checking the actual data: for
these 93 files, the single detected speaker's share of total audio
duration ranges ~42-90% (not 100%), meaning the rest of each file is
silence/non-speech, not a second speaker being missed. This is consistent
with a real mix in this corpus of solo short-form clips (no host/
interviewer) alongside longer interview-format talks -- the corpus does
contain files with 2+ speakers detected (median across all 199 files is 2
speakers). It cannot be fully confirmed without a manual listen whether any
of these 93 genuinely had a second speaker that diarization missed, but
none of them show any of the six flags above that would corroborate a real
diarization failure (e.g. suspiciously low target-speaker share, or
implausible speech rate).

**Speech rate** (2.0-3.7 words/sec across the whole corpus, tightly banded)
falls comfortably inside normal spoken-English pace with no outliers --
strong signal that word-to-speaker alignment is working correctly and not
producing garbled/truncated speech.

**Text retention** (median 87% of the original Phase 3 transcript's words
survive into the isolated target-speaker text) is in a plausible range:
high enough that isolation isn't discarding most of the real content, low
enough that it's actually excluding *something* (the other speaker(s),
where present, plus words that fell on turn boundaries).

## Caveats / what this audit does NOT verify

- **Not verified**: whether the *content* of the isolated text is
  coherent, natural-reading speech (vs. e.g. a stitched sentence that reads
  oddly because a few words from a turn boundary got dropped). The
  structural metrics above are a strong proxy but not a substitute for
  spot-listening to a sample of files.
- **Not verified**: whether the target-speaker identification heuristic
  (`longest_total_duration` -- see `configs/diarization.yaml`) ever picked
  the wrong person on a file where an interviewer/host talked almost as
  much as Sadhguru but still less overall. The `low_target_speaker_share`
  flag (0 hits) is the best available proxy for this and found nothing,
  but a heuristic tie-break failure close to 50/50 wouldn't necessarily
  trip that threshold.
- Full per-file metrics for all 199 files, plus the sorted list of the 93
  flagged files, are in `eval/results/diarization_quality_report.json`.
